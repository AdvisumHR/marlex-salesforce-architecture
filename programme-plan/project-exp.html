Overview › EXP

Project EXPGroup expansion (Portugal, Italy, the Philippines)

Marlex group expansion — reuse the proven Spain platform: Portugal and Italy switched on inside the shared org via one reusable playbook, the Philippines stood up on its own brand-org, all after Spain is live and the standard is classified.

3
Epics
15
Deliverables

How it fits together

This project extends the platform Spain proves to the rest of the Marlex group, and its shape differs by country. Portugal and Italy are switched on as country scopes inside the same shared Marlex org, running the identical reusable regional playbook rather than a bespoke build each time. The Philippines already runs its own separate Salesforce org, so it stands up on its own brand-org (like Axxon), rebuilds the standard by reference, and then moves off and retires its existing system.

Because Portugal and Italy run the same playbook, each is a lean sequence rather than a long enumeration: roll out (activate the country scope and apply the regional configuration baseline), validate and rehearse, go live with close support, and connect the local ERP through a routing extension. Either splits into its own org only if a legal, data-residency or process requirement forces it.

The Philippines is heavier because it is a brand-org with an existing org to retire: on top of standing up and configuring the brand-org, validating, going live and connecting the ERP, it inventories its current org, migrates the data into the new brand-org, and decommissions the old one. Its own org accommodates any Asia-Pacific data-residency requirement.

The whole project depends on the shared Spain org being live (after its own go-live) and on the standard being classified — the regions need the standard tagged as group-shared versus Spain-specific before they can reuse it. The order among Portugal, Italy and the Philippines is not yet decided; they may run in parallel where capacity allows. Axxon is not part of this project — it keeps its own org under the Axxon onboarding.

Epics, in order

EXP · Portugal Rollout
4 deliverables

Switches Portugal on as a country scope inside the shared Marlex org, running the reusable regional playbook. A lean four-step sequence: roll out (activate & configure), validate & rehearse, go live & hypercare, and connect the Portuguese ERP through a routing extension. Depends on the shared org being live and the standard classified.

Show 4 deliverables
  • Portugal / Portugal rollout
    Switch Portugal on as a country scope inside the shared Marlex org — no new org — and apply the reusable regional configuration playbook: the Portugal overrides and permission sets, the country-keyed sharing that isolates Portuguese records, the region-scoped org settings and localisation, the regional data structure, the Portugal-specific experience, and compliance. This runs the playbook rather than redesigning configuration; single sign-on for the entity is handled at go-live.
  • Portugal / Portugal validation & rehearsals
    Validate that the shared global components and the Portugal configuration work together, and run the technical rehearsals — integration smoke tests for middleware connectivity, portal access and single sign-on, and confirmation that the sharing rules scope records correctly to the Portuguese business unit.
  • Portugal / Portugal go-live & hypercare
    Bring the Portuguese business unit live inside the shared org — single sign-on for the entity, middleware routing for Portugal, business validation — with no org cutover, and provide two to four weeks of close post-go-live support.
  • Portugal / Portugal ERP integration
    Connect the Portuguese ERP by building its System API on the middleware and extending the shared process flows to route Portuguese transactions to it, updating the routing registry. Nothing is deployed on the Salesforce side — Salesforce keeps calling the same middleware endpoint with the standard payload. Sequenced after the rollout so the country tag exists, and before go-live so live transactions reach the right ERP. Owned by the middleware team.

Show 4 deliverables

  • Italy / Italy ERP integration

EXP · Philippines
7 deliverables

Stands Marlex Philippines up on its own brand-org, adopting the standard by reference. Beyond adoption & configuration, validation, go-live and ERP routing, it carries the extra weight of retiring an existing org: inventory, data migration into the new brand-org, and decommissioning the legacy org. Its own org handles any Asia-Pacific data-residency requirement. It is the only expansion unit with a legacy org to retire.

Show 7 deliverables
  • Philippines / Philippines org inventory & migration scope
    Catalogue the metadata and data in the existing Philippines Salesforce org — a fairly new, small org — and classify each item as retire, migrate or modernise, mirroring the main discovery scoped to the Philippines. Identify the integration touch-points, custom code and regional fields that must port to the new brand-org. Produces the inventory and migration-scope statement the data move consumes and the decommission targets.
  • Philippines / Philippines brand-org standard adoption & configuration
    Stand Marlex Philippines up on its own dedicated Salesforce brand-org — an independent brand like Axxon, not a scope inside the shared org — adopting the group standard by reference (rebuilding its brand layers from the Marlex patterns and deploying the group-shared modules, not a copied template) and configuring the brand-org: org settings, security model scoped to the org (no country tag needed — the org boundary is the isolation), localisation, experience, and compliance under the Filipino Data Privacy Act. The Philippines is the only expansion unit carrying a legacy Salesforce org to retire.
  • Philippines / Philippines validation & rehearsals
    Validate in the Philippines brand-org that the by-reference rebuild of the standard plus the Philippines configuration work correctly, and run the technical rehearsals — integration smoke tests for middleware connectivity and single sign-on, latency tests for the region, and confirmation that the org boundary keeps data isolated with no cross-org leakage.
  • Philippines / Philippines go-live & hypercare
    Go-live of the Philippines brand-org — activate Philippines users on their own org, single sign-on, middleware routing — a standalone brand-org go-live like Axxon, with two to four weeks of close post-go-live support.
  • Philippines / Philippines ERP integration
    Connect the Filipino ERP by building its System API on the middleware — handling Philippine peso currency and the international data-transfer mechanism where the ERP requires it — and extending the shared process flows to route the Philippines tenant to it, updating the routing registry. The Philippines is a separate brand-org tenant on the shared middleware, but still calls the same middleware endpoint with the standard payload. Owned by the middleware team.
  • Philippines / Philippines data migration
    Migrate Accounts, Contacts, Opportunities and any Philippines-specific records from the existing legacy Philippines Salesforce org into the new brand-org — not into the shared Marlex org, since the Philippines runs its own org. It reuses the main migration pipeline framework with a Philippines-source adapter, applies reconciliation and data-quality validation per the inventory, and rehearses on a full-copy sandbox before cutover. The Philippines is the only expansion unit with a legacy org to consolidate.
  • Philippines / Legacy Philippines org decommission
    After the Philippines cutover and hypercare, decommission the legacy standalone Philippines Salesforce org once its data has consolidated into the new brand-org: archive snapshot for audit, retire users, cancel the licence, and document the final state. Consolidating the legacy org removes the cost of maintaining a duplicate org.
