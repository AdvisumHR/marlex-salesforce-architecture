Project MKTMarketing Cloud

Marketing Cloud in two waves, in one org throughout — finite campaigns now against the current recruitment data to earn back the licence, then a re-point onto the rebuilt model after go-live.

How it fits together

This project runs Marketing Cloud Next and Data 360 in two deliberately separated waves, and both waves live in the same org throughout. Because the recruitment rebuild happens in place, there is no reinstall and no separate marketing org: Wave A earns a return on the licence now, and Wave B re-points the architecture onto the rebuilt model once it is live.

Wave A builds a finite set of business-to-business and business-to-consumer campaigns against the current recruitment data, on the licence that has been paid since early 2026. Data Cloud ingests Contact records only — no identity resolution and no multi-org hub — and the campaigns are designed as finite from day one, winding down at cutover. This returns value on the licence within its term without wiring the full Data Cloud design to a data model that is about to be replaced.

Wave B re-points Data Cloud and Marketing Cloud onto the rebuilt native model after the recruitment cutover, on clean native data. The work is to move the Data Cloud data streams and identity-resolution mappings off the old recruitment schema and onto the rebuilt objects, carry the Wave A campaigns and reusable customisations forward, and switch on the full architecture — identity resolution, calculated insights, full campaign capability, and the hub-and-spoke topology, with the Spain org as the home Data Cloud, Axxon as a companion org, and Portugal and Italy as regional data spaces inside the home org.

A few boundaries hold. The Philippines stays out of Marketing Cloud and Data 360 scope for now — its brand-org is not a companion in this phase. And the marketing go-live can be timed to the campaign calendar; it need not fall on the same date as the recruitment cutover. And the Wave B target architecture — the hub-and-spoke topology — is a proposed design still to be confirmed; the two-wave sequencing is what is settled.

Epics, in order

MKT · Marketing Cloud — Wave A
3 deliverables

Earns a return on the Marketing Cloud licence now, before the rebuild goes live, by running finite campaigns against the current recruitment data. Data Cloud ingests Contact records only — no identity resolution, no multi-org hub — so no effort is spent wiring the full architecture to a model that is about to be replaced. The campaigns are finite by design and wind down at cutover, returning value on a licence that is already being paid for.

Show 3 deliverables
  • MC Wave A / Data Cloud set up on the current org
    Set Data Cloud up on the current recruitment Salesforce org to ingest Contact records only — no identity resolution, no calculated insights, no multi-org connection. The scope is kept deliberately narrow so Data Cloud credits are not spent on unclean candidate data and the first wave of campaigns stays finite and manageable.
  • MC Wave A / Wave A campaign use cases designed and built
    Design and build a small set of finite business-to-business and business-to-consumer campaign use cases in Marketing Cloud against the Contact data on the current org. The campaigns are finite by design and wind down at cutover; the wave proves the platform and returns value on the licence that has been paid since early 2026.
  • MC Wave A / Wave A run and wound down at cutover
    Run the Wave A campaigns through the window before the recruitment cutover, then wind them down cleanly at cutover: pause every live journey, archive the wave's assets, and record which customisations — flows and journey templates — are worth promoting into Wave B.
MKT · Marketing Cloud — Wave B
2 deliverables

Re-points Marketing Cloud and Data Cloud onto the rebuilt native model after the recruitment cutover, on clean native data. Because the topology is in-place, the platform stays in the same org as the Wave A install — no reinstall — so the work is to move the data streams and identity-resolution mappings off the old schema onto the rebuilt objects and carry the Wave A campaigns forward. Identity resolution, calculated insights and the hub-and-spoke topology turn on here: the Spain org as home Data Cloud, Axxon as a companion, Portugal and Italy as regional data spaces. The Philippines is out of scope for now, and the go-live can be timed to the campaign calendar.

Show 2 deliverables
  • MC Wave B / Wave B re-point: data streams, identity resolution and use cases
    Re-point the Data Cloud data streams and the identity-resolution and profile-unification mappings from the old recruitment schema onto the rebuilt native objects — in place, in the same org as the Wave A install, with no reinstall. Carry the Wave A use cases and the promotable customisations forward, switch on full campaign capability including calculated insights, and onboard the first companion org (Axxon). Portugal and Italy are regional data spaces inside the home org rather than separate companions; the Philippines is out of scope for now. The hub-and-spoke topology described here is a proposed target design still to be confirmed.
  • MC Wave B / Wave B go-live and re-point cutover
    Switch live campaign traffic onto the re-pointed native-object data streams, retire the old recruitment-schema streams, and validate the companion-org data flows. Because everything stays in the same org, this is a data-stream re-point rather than an org-to-org move; the go-live is timed to the campaign calendar and may fall on a different date from the recruitment cutover.
